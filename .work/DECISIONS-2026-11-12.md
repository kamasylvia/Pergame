## 1. UUIDv7 全统一(已执行,不可逆但无数据可丢)

- 三选一你拍了 UUIDv7。我执行时把 **migration 0006/0007/0008 合并**了(0007/0008 文件删除),理由:库已清空,`_sqlx_migrations` 已清,留着拆分文件只剩考古价值。

- Snowflake 的 `sf` 前后端 string 互转模块已删。前端 id 本来就是 string,**零改**,只改了 target users 复选框一处。

## 2. 快照直写:读"首个可达 target"(已执行)

- 多 target 内容一致(全写),读只读第一个连得上的。**隐含假设**:全写成功时各 target 内容一致;如果某次写部分失败,各 target 的快照集合会漂移,读到的可能是旧清单。我没做跨 target 对账(复杂度高),只保证"读到的是某个 target 的完整一致视图"。
- 要不要对账?我的判断:不要。失败会 warning,用户重跑一次快照就收敛。

## 3. 零 target 的 job zip 是一次性的(已执行)

- `GET /api/backup/:jobId/download` 读一次就删内存。刷新页面再点 = 404。理由:防内存泄漏。前端 download_url 展示区已支持(之前就是为它留的)。
- 备选:保留到 job 过期。需要就改,一行。

## 4. 还原 force 门默认拒绝非空(已执行)

- 非空工作区还原必须 force=true。**现有的"两步确认"前端流程不变**(第一次点出 preview,第二次执行),只是第二次请求现在带 force。空工作区(如新实例恢复)无 force 直接过。
- Trash 不计入"非空":回收站有东西不挡还原。

## 5. 删账户:target 对象不动(已执行)

- 删账户清主桶 `{uid}/` + DB 行,但**用户 S3 上的快照不动**(那是用户自己的桶,删了等于删用户财产)。门禁要求先 empty targets。
- 最后一个 admin 不能删自己(防锁死)。

## 6. 只读收紧拿掉了 /api/users/@me 豁免(已执行)

- 备份/还原时,改自己的设置会被 423。fork 就是这么定的(快照一致性)。**副作用**:前端设置页在备份时会保存失败——MaintenanceBanner 已经会显示只读提示,用户能看懂。
- 登录/刷新 token 不受影响(`/api/auth` 仍豁免)。

## 10. backup_targets INSERT 占位符错位(线上抓到,已修 v0.0.6)
