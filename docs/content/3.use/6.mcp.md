Pergame speaks the [Model Context Protocol](https://modelcontextprotocol.io): an AI
agent can search, read and edit your notes through the same API and the same
permissions you have in the interface.

Access is granted by a **personal API token**. A token acts as you — it can reach
everything you can reach, and nothing else.

## Create a token

1. Open **Settings → Tools → API tokens**.
2. Name the token after the place it will live (`laptop-claude`, `ci-script`, …).
3. Click **Create token** and copy the value immediately.

::warning
The token is shown once. The server stores only a SHA-256 hash of it, so a lost
token cannot be recovered — create a new one and revoke the old.
::

The list shows when each token was created and when it was last used, so an
unused one is easy to spot. **Revoke** deletes it immediately: the next request
with that token is rejected.

## Connect a client

Point the client at the streamable HTTP endpoint and pass the token as a bearer
header:

```txt
https://your-instance.example.com/api/mcp
Authorization: Bearer pgm_...
```

The URL shares the instance origin with the interface (the frontend proxies
`/api/**` to the backend). No extra port has to be published.

### Claude Code

```bash
claude mcp add --transport http pergame https://your-instance.example.com/api/mcp \
  --header "Authorization: Bearer pgm_..."
```

### Clients configured with a JSON file

```json
{
  "mcpServers": {
    "pergame": {
      "type": "http",
      "url": "https://your-instance.example.com/api/mcp",
      "headers": {
        "Authorization": "Bearer pgm_..."
      }
    }
  }
}
```

::note
Some clients call this transport `streamable-http` rather than `http`. Both mean
the same thing here; follow whatever spelling your client documents.
::

## Available tools

| Tool            | Arguments                       | What it does                                                        |
| --------------- | ------------------------------- | ------------------------------------------------------------------- |
| `search_notes`  | `query`, `limit?`               | Full-text search over your documents; returns ids and a snippet.     |
| `list_children` | `folder_id?`                    | Lists a folder's direct children; omit the id for the top level.     |
| `read_note`     | `id`                            | Returns the markdown source, title, role and timestamps.             |
| `create_note`   | `folder_id?`, `name`, `content?` | Creates a document; an unwritable folder falls back to the top level. |
| `update_note`   | `id`, `content?`, `name?`       | Edits the markdown and/or the title; omitted fields stay as they are. |
| `move_node`     | `id`, `new_folder_id?`          | Moves a node; omit or null the parent to move it to the top level.    |
| `delete_node`   | `id`                            | Moves the node and its subtree to the trash (restorable).             |

Every call runs as the token's owner: shared folders are editable only where you
have write access, another account's documents answer *forbidden*, and moving
someone else's node is refused even with write access (only the owner or an
administrator may move it).

A node cannot be moved into itself or into its own subtree — that would detach
the subtree from the tree — so the call is rejected instead of silently doing
nothing.

## What agents cannot do

- **Delete permanently.** `delete_node` is the same soft delete as the interface:
  the subtree lands in the trash and stays restorable until the retention period
  ends.
- **Bypass permissions.** Tokens are not an administrator channel. Sharing rules,
  workspace visibility and read-only locks apply exactly as in the browser.
- **Write during a backup or restore.** While either is running the workspace is
  read-only; write tools answer with error `-32023` and
  `data.reason: "backup_in_progress"`. Reading and searching keep working, so an
  agent can explain why it cannot edit instead of guessing.

## Token hygiene

- One token per client, so revoking a laptop does not break a server.
- Treat the value like a password: environment variable or secret store, never a
  committed file.
- Revoked and rotated tokens are recorded in the instance logs
  (`mcp.token.create`, `mcp.token.revoke`), together with the write calls made
  through them (`mcp.tool.*`).

::note
There is no rate limit on token usage. That is deliberate for single-user and
family instances: the token is the capability, so revocation is the control. If
you expose the instance publicly and want a limit, apply it at your reverse
proxy.
::

## Troubleshooting

**`406 Not Acceptable` / "Client must accept both application/json and
text/event-stream"** — the request reached the backend without the media types
the MCP transport requires. This happens when something in front of the instance
rewrites the `Accept` header. The bundled frontend proxy forwards it correctly; if you run your own
reverse proxy, let `Accept` through untouched.

**`401 Bad access token.`** — the token is missing, mistyped, or was revoked.
Tokens always start with `pgm_`.

**Startup hangs with no output** — some clients keep the standalone event stream
open. That stream is optional; if your client needs server-initiated events,
connect it to the backend port directly instead of through the frontend proxy.
