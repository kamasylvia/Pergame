A plugin is a folder with two files:

```
my-plugin/
  manifest.json   # identity, contract version, capabilities
  main.mjs        # ES module, default export = Plugin class
```

```json
{
  "id": "word-count",
  "name": "Word Count",
  "version": "0.1.0",
  "apiVersion": "1",
  "entry": "main.mjs",
  "capabilities": ["nodes:read", "ui"]
}
```

`apiVersion` is the host contract major. A plugin built for a different major is refused instead of silently breaking.

## Installing

An administrator uploads the plugin zip under **Settings → Plugins**. The manifest is validated on the server before anything is stored; the archive must contain `manifest.json` and the entry it names.

Installing is instance-wide, but **every user approves capabilities for themselves**: a plugin does nothing for you until you tick at least one of its capabilities. Plugins with nothing granted are not loaded at all.

Official packs ship with the app (`/plugin-packs/recent-files.zip`, `daily-note.zip`, `web-clipper.zip`).

## Writing one

```js
export default class WordCount {
  async onload(ctx) {
    ctx.ui.command('count', 'Count documents', async () => {
      const nodes = await ctx.nodes.listChildren();
      ctx.ui.notice(`${nodes.filter(node => node.role === 3).length} documents here`);
    });

    ctx.ui.ribbon('🧩', 'Word count', () => ctx.ui.notice('See the command palette'));
  }

  onunload() {
    // Everything registered through `ctx` is reclaimed automatically.
  }
}
```

| API | What it gives you |
|---|---|
| `ctx.nodes` | read, create, update, delete nodes — same permissions as your account |
| `ctx.resources.upload(file, parentId?)` | upload an attachment |
| `ctx.search.fulltext(q)` / `.query(dql)` | search and Dataview queries |
| `ctx.settings.get/set/delete` | your private key/value store for this plugin |
| `ctx.ui.notice(msg)` | toast notification |
| `ctx.ui.command(id, title, run)` | entry in the command palette (Plugins section) |
| `ctx.ui.ribbon(icon, title, run)` | button in the sidebar dock |
| `ctx.markdown.registerCodeBlock(lang, render)` | render a fenced block (` ```lang `) |
| `ctx.markdown.registerContainer(name, render)` | render `:::name … :::` |
| `ctx.markdown.registerPostProcessor(fn)` | rewrite rendered HTML once per document |
| `ctx.editor.registerCmExtension(ext)` | append a CodeMirror 6 extension |
| `ctx.net.fetch(url)` | browser fetch, limited to the declared domains |
| `ctx.net.proxy(url)` | **server-side** fetch, for pages the browser cannot read (CORS) |

Every registration returns a `Disposable`; unloading a plugin releases all of them.

## Capabilities

| Capability | Grants |
|---|---|
| `nodes:read` | read nodes and run searches |
| `nodes:write` | create, update, delete nodes |
| `ui` | notifications, palette commands, dock button |
| `markdown:render` | Markdown block/container hooks |
| `settings` | the private key/value store |
| `net:example.com` | network access to that domain and its subdomains |
| `net:*` | any domain — ask for a specific list instead |

Network calls are restricted to `GET`/`POST` and 8 MiB per response, whatever the manifest says.

## Clipping pages without browser automation

`ctx.net.proxy(url)` fetches on the server, so a clipper does not need a browser automation service or a browser extension. Two limits worth knowing:

- the proxy refuses private addresses (`localhost`, RFC1918, link-local) and only reaches hosts the manifest names;
- it carries **no browser cookies**. A site that needs a login has to be handled by asking the user (paste the page, or store that site's cookie in plugin settings).

`ctx.net.proxyBinary(url)` does the same for bytes, which is how a clipper stores images as attachments.

### Web clipper (official pack)

`web-clipper.zip` replaces what the SiYuan *ReadItLater* plugin did, without the browser service:

- **Clip a URL** (palette or dock button): a dialog asks for the URL, an optional title, tags and a folder.
- **Clip from clipboard** and **Clip every URL in the clipboard** (batch).
- **Article extraction**: Mozilla Readability + Turndown, relative links absolutized, images downloaded through `proxyBinary` and stored as attachments.
- **Per-type handling**: Zhihu answers/columns (your cookie, set in plugin settings), YouTube/Bilibili/Vimeo/TikTok embeds via oEmbed, Stack Exchange (question + best answer), Bluesky, Mastodon, GitHub issues/repos, Wikipedia summaries, plain-text fallback.
- **Templates**: `{{ var | filter }}` and `{% for %}` loops, one default per content type; override with the `template_<type>` setting (defaults are written to `template_defaults` on load).

Not ported from ReadItLater: the image-bed uploader, YouTube Data API metadata, Twitter/X and Pinterest (they need authenticated APIs), and “insert at cursor” (the plugin API has no editor-cursor hook yet).

## Loading during development

Point the dev server at a local plugin URL:

```bash
NUXT_PUBLIC_DEV_PLUGINS="http://localhost:5173/my-plugin" bun run dev
```

The URL must serve `manifest.json` and the entry file. A plugin that throws during `onload` is disabled and reported; the rest keep running.

## Limits

- Plugins run in the page realm: install only code you trust.
- They cannot see more than the signed-in user, and they cannot read other browser tabs.
- Commands/ribbons/markdown hooks are the whole UI surface today; views and settings tabs come later.
