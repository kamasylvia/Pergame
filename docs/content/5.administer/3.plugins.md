:::warning
The plugin host is a preview: the data layer (`nodes`, `resources`, `search`, `settings`), notifications, commands, a sidebar dock button and network access are exposed. Views, settings tabs and Markdown hooks land in the next phases.
:::

A plugin is a folder with two files:

```
my-plugin/
  manifest.json   # identity, contract version, capabilities
  main.mjs        # ES module, default export = Plugin class
```

```json
{
  "id": "word-count",
  "name": "Word Count",
  "version": "0.1.0",
  "apiVersion": "1",
  "entry": "main.mjs",
  "capabilities": ["nodes:read", "ui"]
}
```

`apiVersion` is the host contract major. A plugin built for a different major is refused instead of silently breaking.

```js
export default class WordCount {
  async onload(ctx) {
    ctx.ui.command('count', 'Count documents', async () => {
      const nodes = await ctx.nodes.listChildren();
      ctx.ui.notice(`${nodes.filter(node => node.role === 3).length} documents here`);
    });

    // A button in the sidebar dock, next to the built-in shortcuts.
    ctx.ui.ribbon('🧩', 'Word count', () => ctx.ui.notice('Click a command instead'));
  }

  onunload() {
    // Everything registered through `ctx` is reclaimed automatically.
  }
}
```

Commands show up in the command palette under **Plugins**; both registrations return a `Disposable`, and unloading the plugin removes them.

## Capabilities

| Capability | Grants |
|---|---|
| `nodes:read` | read nodes and run searches |
| `nodes:write` | create, update, delete nodes |
| `ui` | notifications, palette commands and a dock button |
| `markdown:render` | Markdown block and container hooks |
| `settings` | a private key/value store |
| `net:example.com` | network access to that domain (and its subdomains) |
| `net:*` | any domain — ask for a specific list instead |

Network calls are restricted to `GET`/`POST` and 8 MiB per response, whatever the manifest says.

## Loading during development

The host is idle until an instance lists plugin URLs:

```bash
NUXT_PUBLIC_DEV_PLUGINS="http://localhost:5173/my-plugin,http://localhost:4000/other" bun run dev
```

Each URL must serve `manifest.json` and the entry file. A plugin that throws during `onload` is disabled and reported, and the rest keep running.

A reference plugin ships at `/plugins/demo/`; point the variable at `http://localhost:3000/plugins/demo` to see it load.

## What plugins cannot do

- Ask for more than the signed-in user can do — every call goes through the same REST endpoints and permissions as the interface.
- Escape the module sandbox: plugins run in the page realm, so install only code you trust.
- Register anything without a handle: every registration returns a `Disposable`, and `onunload` releases all of them (plus the host's own cleanup).

Installing plugins from the admin UI, the plugin registry and Markdown hooks are tracked in issue #8.
